# 03. 성능·확장성·비용 실험 계획

**상태:** AWS 비교 실험 프로토콜입니다. [Phase 1-5 로컬 측정](../experiments/README.md)은 별도로 기록하며, AWS 기준선은 미측정입니다.

## 부하 시나리오

- **유휴 상태:** 요청은 없지만 최소 용량을 유지하는 상황.
- **일정한 부하:** 메뉴 조회와 주문 쓰기가 일정 비율로 지속되는 상황.
- **단일 테넌트 폭증:** 브랜드 A만 프로모션 부하를 받고 B/C는 기본 부하 유지.
- **전체 테넌트 폭증:** A/B/C 모두 동시에 증가.
- **장애:** Worker/Task 하나를 종료하거나 공유 인스턴스의 오류를 주입.

애플리케이션 코드, 데이터 분포, AWS Region, 테스트 입력을 최대한 동일하게 유지합니다. 가능한 경우 자원 상한과 가용성 목표를 맞춥니다. 런타임 워밍업 후 지속 측정하고, 시나리오별 **3회 이상 반복**하며 환경 버전과 제약을 기록합니다.

## 주요 측정값

- **브랜드별:** RPS, API p50/p95/p99, 오류율, 성공 주문 수, 주문→전달 지연, 실제 비즈니스 중복 처리 수(목표 **0건**), 교차 테넌트 접근 차단 여부.
- **인프라:** ECS Task·CPU·메모리, EC2 ASG 인스턴스 수/이용률, Capacity Provider 확장 이벤트, PENDING Task 수, 인스턴스 기동·Task 준비 각각의 지연, SQS 적체량·최고 대기 시간, DB 이용률, 전환 시 중단 시간.

## 단계별 관측·검증 절차

**초기 Source 기준선(3단계):** k6로 브랜드별 RPS·p95·오류율을 저장하고, AWS 기본 CloudWatch ECS/ALB/RDS/SQS 지표, JSON 로그, 부하·확장 이벤트 시각을 함께 기록합니다. 이때 OpenTelemetry, 별도 Collector, Prometheus/Grafana나 Trace 백엔드 배포는 필수가 아닙니다.

**마이그레이션 후 관측 고도화(6단계):** CloudWatch 단독 또는 추가 관측 도구를 결정하고 대시보드·경보·필요한 Trace를 구축합니다. **최종 Source/Target 비교(7단계)는 두 환경의 계측 설정을 동일하게 맞춰 재측정**해야 합니다.

**최종 증거 목표:** 브랜드별 성능 그래프, ECS Task/EC2 ASG 확장 타임라인, 장애 로그, 경보 및 선택한 추적 방법의 증거를 남깁니다. 로그·Trace에서 비밀과 개인정보는 제거합니다. [관측 요구사항](08-observability.md).

## 검증할 가설

- **H1:** 낮은 평균 이용률에서는 공유 구조가 브랜드별 유휴 컴퓨팅 비용을 줄인다.
- **H2:** 독립 구조가 일부 Noisy Neighbor 영향을 더 잘 제한한다.
- **H3:** 공유 환경의 용량 예약과 공정성 제어는 비용과 버스트 격리 사이의 트레이드오프를 만든다.
- **H4:** 점진적 브랜드 전환은 서비스 중단을 제한하면서 데이터 정합성을 보호할 수 있다.

위 내용은 **가설**이며 결과가 아닙니다.

## 비교 단계 및 자동 확장 실험

1. **기준선:** 브랜드별 ECS Fargate. 유휴·정상·폭증 부하의 Task 자원 사용량과 비용을 기록합니다.
2. **목표:** 공유 ECS on EC2, EC2 Capacity Provider + ASG. 같은 애플리케이션과 입력에서 비용·지연·확장성을 비교합니다.
3. **확장 실험:** 낮은 기본 Task/EC2 용량으로 시작하여 브랜드 A 부하를 증가시킵니다. ECS Service Auto Scaling 정책이 Task 수를 늘리고, 호스트 용량이 부족해지면 Capacity Provider가 ASG 증설을 유도하는지 확인합니다.
4. **원인 분리(선택):** 공유 Fargate 임시 실험을 통해 테넌트 통합 효과와 Fargate→EC2 실행 환경 변경 효과를 분리합니다. 이 단계를 생략했다면 총 개선을 공유 효과만으로 해석하지 않습니다.
5. **추후 고도화(선택):** Warm Pool 유무의 EC2 기동/준비 시간 비교.

## 비용 비교 방법

**실험 중 실제 AWS 청구액**과 **30일 운영을 가정한 모델링 비용**을 구분합니다. Fargate/EC2 컴퓨팅, ALB 시간·LCU, RDS, SQS, 로그, NAT 또는 VPC Endpoint, 데이터 전송 등 실제 배포된 항목을 포함합니다. 브랜드 수, 가용성 요구, 트래픽 분포를 명확히 동일 조건으로 설정합니다. 손익분기점은 측정·산정 후에만 결론 내립니다.

## 증거 자료

k6 테스트 코드, 원시 JSON/CSV, 메트릭 캡처, Terraform 설정, 요금 가정, 결론의 한계를 보관합니다. OrderServ 공식 절감률과 Scale-out 개선값을 우리 프로젝트의 성과로 사용하지 않습니다.
